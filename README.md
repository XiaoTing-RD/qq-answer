# 海参的唤醒 v1.5（QQ 消息朗读 + 语音回复）

一个 Android 独立应用：读取 QQ 通知 → 用 TTS 朗读 → 你说话 → 转成文字 → 复述并问「确认发送吗」→ 你说「确认」后才通过 QQ 通知的「直接回复」接口发出。

不需要 root、不需要 Xposed/LSPosed、不修改 QQ 本体。用的是 Android 官方「通知使用权 + 通知直接回复（RemoteInput）」能力。

- 已在本机验证：`assembleDebug` 构建成功，`lintDebug` 通过（只有资源/兼容性类警告）
- 现成安装包：`C:\Users\lenovo\Desktop\海参的唤醒.apk`（约 68 MB，内置中文离线识别模型，debug 签名）
- 未在真机上做端到端测试（本机没有连接安卓设备），首次使用请先拿小号/朋友测试
- 源码：https://github.com/XiaoTing-RD/qq-answer （tag：`v1.5`）

## 0. v1.5 更新（本次重点）

v1.4 已经能用离线 Vosk 识别，但实测暴露出：清后台后监听断、离线性收音太小要喊、确认后发送失败、一次连发会漏消息、背景太单调。v1.5 逐条处理：

1. **后台恢复监听**：记住「骑行模式」开关；清后台/被杀后重新打开 App 会自动拉起服务，并主动 `requestRebind` 重新绑定 QQ 通知监听
2. **离线收音增强**：不再用 Vosk 自带录音，改成 App 自己的 AudioRecord（优先 MIC），逐块自适应增益（1~5 倍，安静时自动放大，正常音量即可）；带 1.8 秒静音断句；确认阶段用「确认/确定/发送/取消/不对/等一下」的受限语法，避免乱识别
3. **发送失败可诊断、可兜底**：发送失败会明确说是「QQ 通知没有直接回复按钮」还是「通知失效/发送异常」；App 里新增「QQ 直接回复：可用/不可用」和「最近发送失败」；失败通知提供「复制并打开QQ」（由前台 Activity 复制，避免后台剪贴板被系统拦截）
4. **消息贮存栈**：连发多条时不再因为队列上限丢弃；每条按「第 X 条，共 N 条」播报；读完有 **4 秒** 决定回不回；说「回」后再用 12 秒说内容；确认 12 秒；栈空才停
5. **背景与 Q 版 UI**：内置 5 张樱色背景，每次启动随机一张，之后每 12 秒淡入切换；圆体字、爱心小图标、圆润粉色按钮、粉白卡片、SAKURA RIDE 小徽章，整体更少女

首次打开仍会准备离线模型（约 68 MB，几秒）。**你这台手机建议识别引擎直接选「离线识别（Vosk）」**，再点「测一测」确认显示「识别成功（离线）」。

> 如果发送仍失败，先看 App 里「QQ 直接回复」是否显示「不可用」和「最近发送失败」原因。如果 QQ 通知本身没有系统直接回复接口，需要下一步加无障碍自动发或手动粘贴；这条需要你确认。

如果连离线也失败，按第 7 节排查，并把「最近错误」原文发我。

## 1. 为什么不是「QQ 插件」

QQ 没有公开的插件 API。市面上的 QQ 机器人/插件基本靠改包、Xposed 或协议登录，容易封号。这个方案完全在 QQ 外面工作：

1. 系统把 QQ 的新消息通知交给本应用（通知使用权）
2. 本应用朗读通知里的「谁 + 说了什么」
3. 语音识别把你说的话转成文字
4. 复述草稿，等你语音确认
5. 用 QQ 通知自带的 `RemoteInput` 直接回复，不打开聊天界面

因此有两个硬条件：**QQ 必须弹通知**，且通知里带**可直接回复的输入框**（大部分 QQ 8.x + Android 7 以上都支持）。

## 2. 功能

- **只朗读指定好友，默认「林霏」**；其他人的消息完全不读、不回复
- 朗读好友消息，默认不读群消息（可开；群消息也只匹配这个名字）
- 消息里自动带发送者昵称
- 说完自动复述草稿，只有听到「确认/确定/发送」等明确词才发
- 说「不回/不用/取消/算了/等一下」跳过或取消
- 识别不清时最多重试一次，仍不清楚就取消，绝不乱发
- 识别失败会念出具体原因（权限/后台被拦/无语音服务/网络等），并写入应用内「最近错误」
- 内置 Vosk 中文离线识别；系统识别被手机拦截时自动切离线，也可手动选「离线识别」
- 应用内提供语音识别自检和 15 秒测试，结果会标明走的是「系统」还是「离线」
- 发送失败会说明原因并保留内容；通知栏可「重试」或「复制并打开QQ」
- App 内显示「QQ 直接回复：可用/不可用」和「最近发送失败」，方便定位是 QQ 通知没有回复接口，还是发送异常
- **消息贮存栈**：连发多条逐条入栈，播报「第 X 条，共 N 条」；每条有 4 秒决定回不回，直到栈清空
- 常驻前台服务；清后台/被杀后重新打开 App 会自动恢复监听并重绑通知权限
- 5 张樱色背景随机启动、每 12 秒淡入轮播 + 落樱飘落动画（素材取自 `流歌\pic`）
- 圆体字、爱心图标、圆润粉色按钮、粉白卡片和 SAKURA RIDE 徽章
- 收到消息可播放手机本地音乐当闹铃（开关可控，自选文件，最长 6 秒，消息栈只首条提醒）
- 声音预设：可莉感高音童声、元气少女、温柔女声、清爽少年、清晰播报
- 通知栏按钮：重听 / 取消 / 停止

## 3. 声音：关于「可莉音」

**原神可莉的原声做不了，也不建议做。** 官方没有可莉 TTS 接口，游戏语音文件有版权，提取/克隆用于自制软件属于侵权；网上所谓「可莉语音包」也大多是拆包素材。所以这里给的是「近似可爱童声」，不是可莉本音。

已内置（在应用里直接选、点「试听」）：

| 预设 | 音高 | 语速 | 感觉 |
|---|---|---|---|
| 可莉感 · 高音童声 | 1.55 | 1.05 | 最接近「小小只」的卡通感，建议配童声引擎 |
| 元气少女 | 1.32 | 1.05 | 活泼但不刺耳 |
| 温柔女声 | 1.08 | 0.96 | 夜间/安静环境 |
| 清爽少年 | 1.18 | 1.00 | 中性、清楚 |
| 清晰播报 | 1.00 | 0.96 | 风大、戴头盔时最清楚 |

更接近的方案（按投入从低到高）：

1. **换一个带童声的 TTS 引擎（推荐先试，零代码）**
   - 安装「讯飞语音+」等带童声/少女声的 Android TTS 引擎
   - 系统设置 → 语言和输入 → 文字转语音（TTS）输出 → 选这个引擎 → 下载中文语音包
   - 回本应用选「可莉感」或「元气少女」，点试听
   - 童声引擎 + 1.1~1.2 音高通常比普通女声硬拉到 1.55 更自然
2. **云端童声（最像，需要 API Key，需我再加一个模块）**
   - 微软 Azure：`zh-CN-XiaoshuangNeural`（童声，气质最接近可莉）、`zh-CN-XiaoyiNeural`（少女）
   - 火山引擎/阿里云也有童声，效果接近
   - 需要联网和密钥；可以离线合成到本地再播，减少流量
3. **本地神经网络 TTS（离线、免费，但工程量大）**
   - sherpa-onnx + 中文 VITS 童声模型，装进 App 里，首次下载模型后完全离线
4. **可莉原声/克隆：不做。** 没有官方授权渠道。

现在这个版本用的是系统 TTS（离线可用），所以换引擎就能明显改变音色，不用改代码。

## 4. 部署（最快路径：直接装 APK）

### 4.1 传到手机并安装

1. 把 `C:\Users\lenovo\Desktop\海参的唤醒.apk` 传到手机：
   - USB 数据线拷贝，或
   - 用 QQ「我的电脑/文件传输助手」发到手机 QQ，再保存到文件管理器
2. 在手机上点开 APK。系统提示「未知来源」时，允许当前文件管理器/浏览器安装。
3. 安装完成后先不要急着开开关，按下面顺序授权。

> 这个 APK 是 debug 签名，只适合自己用。以后如果用 Android Studio 重新构建，签名会变，安装前要先卸载旧版。

### 4.2 应用内四项授权（按顺序点）

打开「海参的唤醒」：

1. **通知使用权**
   - 点「通知使用权」按钮
   - 在列表里找到「海参的唤醒 · QQ 消息」，打开开关
   - 如果按钮没跳到列表：设置 → 通知与状态栏 → 通知使用权（不同品牌叫「特殊应用权限」「通知读取权限」）
2. **麦克风**
   - 点「麦克风」→ 允许
   - 必须选「仅在使用中允许」或「始终允许」，**不要选「仅本次」**；选了「仅本次」，你锁屏/离开应用后系统会收回麦克风，语音回复必然失败
3. **通知权限**
   - Android 13 以上会弹系统授权，点允许
   - 如果已经拒绝过，按钮会跳到本应用的通知设置，手动打开
4. **后台运行**
   - 点「后台运行」→ 允许忽略电池优化
   - 再到系统设置里补充（不同品牌路径见下）

状态全部变成绿色「已授权」后，点「试听」，确认能听到中文女声。

### 4.3 设置只读对象（默认「林霏」）

应用「骑行模式」卡片里有：

- 开关「只处理这个人的消息」：默认开
- 输入框：默认填了「林霏」
- 「保存」按钮

要点：

- 这里填的是 **QQ 里你给对象设置的备注名**（如果没设备注，就填通知标题显示的昵称）
- 必须和通知标题完全一致，多一个字、少一个空格都不行；改完点保存，立即生效
- 其他人的消息会被直接忽略，不会朗读、不会回复
- 如果对象改了备注，这里也要同步改
- 如果开启「朗读群消息」，群里只有这个昵称发的消息会被读（仍建议关群）

### 4.4 设置 QQ（关键）

QQ → 左上角头像 → 设置 → 消息通知：

- 新消息通知：开
- **通知显示消息详情：开**（不开只能读到「你收到一条新消息」，无法朗读内容）
- 锁屏显示消息详情：开（可选）
- 群消息：按需；本应用默认不读群，需要读群时在应用里打开「朗读群消息」
- 免打扰的群/好友不会发通知，本应用自然也读不到

系统设置 → 应用管理 → QQ → 通知：

- 允许通知：开
- 锁屏通知：显示内容
- 后台运行/省电策略：不受限制

部分 ROM 还要在 QQ 里关掉「PC 登录时手机静音通知」之类的选项，否则手机不弹通知。

### 4.5 设置提醒音乐（可选）

1. 应用「声音与闹铃」卡片里，打开「收到消息时播放本地音乐」
2. 点「选择本地音乐」，用系统文件选择器挑一首手机里的歌（mp3/m4a/flac/ogg 等）
3. 选完会自动打开开关，并显示文件名；点「试听闹铃」确认音量
4. 之后每次收到对象的消息：先播放最多 6 秒音乐，然后朗读消息、进入语音回复
5. 不想用就关掉开关；换歌重新选一次即可

说明：

- 不需要存储权限，走系统文件选择器（SAF）；权限会持久保留
- 音量走「媒体音量」，手机静音/勿扰模式可能不出声
- 如果歌曲被删除、移动，或重启后系统收回了权限，重新选一次；播放失败会自动跳过音乐直接朗读，不影响回复

### 4.6 选择语音识别引擎（v1.5 关键）

应用「声音与闹铃」卡片里有「识别引擎」：

1. **自动（系统失败用离线）**：默认。先用系统语音，遇到 ERROR_CLIENT/无服务/语言不支持等，自动切到离线 Vosk
2. **系统语音识别**：只用系统；你这台手机的系统服务会报「系统拦住了语音识别」，不建议选
3. **离线识别（Vosk）**：只用本地模型；**你这台手机建议直接选这个**

首次准备：

- 打开 App 后会自动准备离线模型，显示「正在准备离线识别模型（首次需要几秒）…」
- 模型约 68 MB，随 APK 打包，不联网；首次会复制到应用专属目录，只复制一次
- 准备完成后显示「离线模型已就绪」，点「测一测」，**正常音量**说一句话，应显示「识别成功（离线）：…」
- v1.5 离线收音会自动放大安静的声音（1~5 倍自适应增益），不用大喊；如果还是太小，先用手机麦测试，蓝牙耳机麦可能更弱

如果测试结果：

- **识别成功（离线）**：语音回复链路已通，可以打开骑行模式
- **识别成功（系统）**：系统服务临时可用；可以继续自动，也可以切离线
- **失败（系统）**：正常，这台手机会被系统拦；切「离线识别（Vosk）」再测
- **失败（离线）**：看「最近错误」；常见是模型准备中/存储空间不足/麦克风被占用

### 4.7 打开骑行模式

回到应用，打开「骑行模式」右侧的开关。

- 通知栏会出现常驻通知「海参的唤醒 · 已开启，等待 QQ 消息」
- 用另一个号给这个 QQ 发一条文字消息测试
- 这个开关会被记住：清后台/被杀后重新打开 App 会自动恢复服务并重绑通知监听

如果通知栏没有常驻通知，说明服务没起来：检查麦克风权限、电池优化、后台限制。

### 4.8 第一次测试脚本

测试号在 QQ 里的备注必须改成「林霏」（或者在应用里暂时关掉「只朗读指定好友」），否则消息会被过滤，看起来像没反应。

如果上一节测试成功（尤其是「识别成功（离线）」），再测真实消息。

让朋友/小号发：`明天九点老地方？`

手机应读出：`林霏说：明天九点老地方？。要回吗？` 然后「滴」一声，**只有 4 秒决定**：

- 说 `回` → 手机问「请说内容」→ 说 `好的，我提前十分钟到` → 复述「确认发送吗」→ 说 `确认`
- 或者 4 秒内直接说 `好的，我提前十分钟到` → 复述 → 说 `确认`
- 什么都不说 → 4 秒后跳过，不会发任何东西

手机复述后只有听到「确认/确定/发送」才发。发送成功会说「已发送」；如果失败，会念出原因，App 里也能看到。

再测连发：让测试号快速连发 3 条，手机应依次播报「第 1 条，共 3 条」「第 2 条，共 3 条」……每条约 4 秒决定，直到栈空。

再测发送诊断：

- App 的「权限与 QQ」卡片会显示「QQ 直接回复：可用/不可用」
- 如果发送失败，看「最近发送失败」的原因；如果是「QQ 通知没有直接回复按钮」，这台 QQ 不能靠通知接口自动发，需要下一步加无障碍或手动粘贴

## 5. 日常使用方式

1. 骑车前：打开应用开关（会记住，下次自动恢复），戴上耳机，手机放口袋/骑行服后袋，锁屏即可
2. 来消息：如果是连发，会先存栈，然后按「第 X 条，共 N 条」逐条读；首条会先放提醒音乐
3. 听完后 4 秒内：说「回」、直接说内容，或什么都不说进入下一条
4. 说「回」后，手机问「请说内容」，再用 12 秒说内容（5~15 个字最稳）
5. 手机复述后说「确认」才发送；说「取消」放弃
6. 不想回：沉默 4 秒，或说「不回」
7. 想重听：下拉通知栏点「重听」
8. 收工：通知栏点「停止」，或在应用里关开关（会记住停止状态）

音量走媒体音量，骑车前把媒体音量调到能听清但不盖住环境声。

## 6. 重要限制（先看，避免踩坑）

- **只读对象靠通知标题匹配**。应用只认「只朗读指定好友」里填的名字，默认「林霏」；QQ 备注/昵称变了就要同步改，否则会被当成其他人过滤掉。
- **必须是 QQ 弹出通知的消息**。你正开着和对方的聊天框、QQ 被系统冻结、对方被免打扰时，都可能不弹通知。
- **只能读文字通知**。QQ 语音消息通常只显示「[语音]」，无法转写；图片显示「[图片]」。本应用不做语音消息转写。
- **自动回复依赖 QQ 通知里的直接回复按钮**。少数 QQ 版本/主题不提供；App 里「QQ 直接回复：不可用」时，只能走「复制并打开QQ」手动粘贴，或者下一步加无障碍自动发送。这不是封号接口，但发送失败时仍需你停车处理。
- **系统语音识别可能被手机限制**，所以内置了 Vosk 中文离线识别。你这台手机前台自检就报 ERROR_CLIENT，建议引擎选「离线识别（Vosk）」；离线识别不依赖系统语音服务，也不联网。
- **消息栈保存在当前服务进程内**。清后台后 App 会自动恢复服务，但已经被系统杀掉那一刻尚未播完的队列无法保证还在；建议把 App 锁定后台/允许自启动。
- **离线识别使用小型中文模型**，短句（5~15 字）识别最稳，长句/口音/风噪仍可能出错；应用会复述草稿让你确认，确认词不清就取消。
- **APK 约 68 MB，模型首次会复制到应用专属目录**，额外占约 68 MB；手机需要留出约 150 MB 空间。首次准备模型需要几秒。
- **提醒音乐依赖你选中的本地文件**。文件被移动/删除、或系统重启后收回 URI 权限时，音乐会自动跳过并直接朗读；重新选一次即可。音乐和朗读都走媒体音量。
- **确认词可能误听**。所以设计成「复述 + 二次确认」，且模糊时取消。但任何语音确认都不是 100% 安全，重要消息建议停车看一眼。
- **不要边骑边看屏幕**。本应用的目标就是让你不看屏幕，但遇到发送失败/识别异常，请靠边停车再处理。
- 蓝牙耳机：朗读会走蓝牙媒体声道；麦克风用手机还是耳机麦取决于机型和识别服务，风噪大时把手机放在胸口口袋更稳。
- Android 14+ 对后台启动麦克风前台服务有限制，本应用是从界面里手动开启的，所以合规；如果系统重启后服务没起来，重新打开应用开关即可。
- 本应用是通知监听器，能读到所有通知标题/内容（系统限制）。代码只处理 QQ 包名，不采集、不联网上传。

## 7. 常见问题

**Q：完全没反应，不朗读**
1. 应用内「通知使用权」是否已授权
2. 开关是否打开、通知栏是否有常驻通知
3. QQ 是否开启了「通知显示消息详情」
4. 给 QQ 发消息时 QQ 是否真的弹了通知（可以锁屏试）
5. 把本应用和 QQ 都加入电池白名单/自启动，锁定后台

**Q：开了「只处理这个人的消息」后完全没反应**
1. 看这个好友在 QQ 通知标题里显示的名字（备注名优先），和输入框里的名字逐字核对
2. 改完点「保存」；名字里不要多空格
3. 临时关掉这个开关测试：如果关掉能读，说明就是名字不匹配
4. 对象改了 QQ 备注后，这里也要一起改

**Q：清后台后重新打开又收不到消息了**
1. v1.5 会自动拉起服务并重绑通知监听；先看「骑行模式」开关是否还开着
2. 看「通知使用权」是否仍是「已授权」；如果被系统收回，重新允许
3. 看通知栏是否有常驻通知；没有的话点一下「骑行模式」开关重新启动
4. 把 App 锁定后台、允许自启动、省电设为无限制；部分 ROM 清后台会连带限制通知监听

**Q：还是不能语音回复（v1.5 先按这个查）**
1. 打开应用 →「声音与闹铃」→「识别引擎」选 **离线识别（Vosk）** → 点「测一测」，正常音量说一句话
2. 看测试结果：
   - **识别成功（离线）**：链路已通，打开骑行模式即可
   - **失败（系统）**：系统服务拒绝第三方调用，正常；切「离线识别」再测
   - **失败（离线）**：看「最近错误」：
     * 「正在准备离线模型」：等几秒再测；首次复制模型需要时间
     * 「离线识别模型加载失败」：检查手机剩余空间（约需 150 MB），重启应用再试
     * 「离线识别录音失败，麦克风可能被占用」：关掉其他录音/语音通话，确认麦克风权限为「仅在使用中允许」
     * 「没听清/等待超时」：靠近手机、一次说 5~15 个字
3. 如果前台自检离线成功、锁屏骑行仍失败：是后台麦克风被系统限制；把本应用设为无限制后台、允许自启动、锁定后台，并确认麦克风不是「仅本次」
4. 蓝牙耳机麦克风是否被采用因机型而异；风噪大时把手机放在胸口口袋，或先用手机麦测试
5. 自动模式第一次会先试系统，系统被拦后切离线；之后本次进程内直接用离线。想彻底跳过系统尝试，直接选「离线识别（Vosk）」
6. 所有失败都会写入「最近错误」，并尽量语音播报，不会再静默跳过

**Q：一直识别成奇怪的内容**
- 换安静环境测试；说话离麦近一点；一次只说一句
- 小模型对长句/口音/风噪会出错，这是正常现象；应用会复述让你确认
- 如果系统识别可用，切「系统语音识别」通常比小模型准；你这台手机系统被拦，就用离线短句

**Q：离线模型占多少空间 / 为什么要准备**
- 模型随 APK 打包，约 68 MB；首次启动复制到应用专属目录，另占约 68 MB
- 只复制一次；更新模型版本才会重新复制
- 准备期间不要杀应用；完成后再测试

**Q：确认后发送失败，出现「回复没有发出」**
- 先看 App 里「QQ 直接回复」：显示「不可用」就是这台 QQ 的通知没有系统直接回复接口，只能走手动/无障碍
- 显示「可用」仍失败，看「最近发送失败」：
  * 「通知已经不在通知栏里了」：消息拖太久/被清理；通知栏点「重试」或「复制并打开QQ」
  * 「QQ 直接回复失败：通知动作已失效」：QQ 通知被更新/替换了；点「重试」，或更新 QQ 后重试
  * 「QQ 通知没有直接回复按钮」：同上，需要无障碍/手动兜底
- 点失败通知里的「复制并打开QQ」：由前台页面复制，内容一定在剪贴板，去 QQ 粘贴发送
- 更新 QQ 到较新版本，关闭 QQ 的「简洁通知/通知过滤」类开关

**Q：喊「确认」没反应 / 一直重问**
- v1.5 确认阶段用的是受限词表：`确认 / 确定 / 发送 / 取消 / 不对 / 等一下`，说短一点
- 确认窗口 12 秒；如果连续两次没听清会取消，绝不乱发
- 看「最近错误」；离线模型加载中或麦克风被占用时，确认也会失败

**Q：连发几条会不会漏 / 4 秒太短**
- v1.5 把队列上限提高到 100，并按通知逐条入栈；播报会带「第 X 条，共 N 条」
- 每条读完只有 4 秒决定；想回就快速说「回」或直接说内容，随后有 12 秒说内容
- 4 秒内没说话会进入下一条，不会发送；如果只是想听不想回，这是预期行为
- 部分 QQ 版本会把多条合并成「N条新消息」且不显示详情，这种情况通知里没有正文，应用无法还原；请在 QQ 开启「通知显示消息详情」

**Q：提醒音乐不响，或只响一下就停**
- 确认「收到消息时播放本地音乐」已打开、下面显示了文件名
- 调大媒体音量；静音/勿扰模式会让它不出声
- 音乐本来只播最多 6 秒，然后开始朗读，这是设计
- 文件被移动/删除、或重启后权限失效：重新点「选择本地音乐」
- 在线音乐/DRM 缓存可能不允许被其他应用播放，换一首本地 mp3/m4a

**Q：声音太机械/不像童声**
- 换 TTS 引擎和中文语音包，见第 3 节
- 音高不要一味拉高，1.1~1.3 往往更自然
- 需要真童声就上云端 TTS（Azure 晓双）或本地神经 TTS

**Q：耗电吗**
- 常驻通知本身很轻；主要耗电来自每次朗读和收音的几十秒。骑行 2~3 小时一般没问题，但建议带充电宝。

**Q：会不会封 QQ 号**
- 本方案不登录协议、不改 QQ、不注入进程，只使用 Android 官方的通知回复接口，风险远低于第三方 QQ 插件。但「自动回复」本身仍建议只对熟人使用，不要群发/营销。

## 9. 工程结构

```
app/src/main/java/com/ridevoice/qq/
  MainActivity.kt        权限引导、开关、只读对象、引擎选择、背景轮播、诊断
  QQListener.kt          通知监听：过滤 QQ、只读对象匹配、去重、重绑、直接回复诊断
  RideService.kt         前台服务 + 状态机 + 消息栈（提醒→朗读→4秒询问→收音→确认→发送）
  Speaker.kt             系统 TTS 封装、音高/语速预设、音频焦点、看门狗
  VoiceInput.kt          系统 SpeechRecognizer 封装、错误分类、音频焦点
  OfflineVoiceInput.kt   Vosk 离线识别：自建 AudioRecord + 自适应增益 + 确认词法
  SpeechRouter.kt        自动/系统/离线引擎路由，系统失败自动切离线
  VoskModelHolder.kt     模型解包/加载单例（StorageService）
  MusicAlarm.kt          本地音乐闹铃：MediaPlayer + 最长 6 秒 + 音频焦点
  ReplySender.kt         从通知 Action + RemoteInput 直接回复，返回失败原因
  FallbackActivity.kt    前台复制剪贴板并打开 QQ（发送失败兜底）
  SakuraView.kt          落樱飘落动画（自绘花瓣，不占资源）
  Prefs.kt               设置、声音预设、只读对象、音乐 URI、识别引擎、发送诊断

app/src/main/assets/vosk-model-cn/   中文离线模型（约 68 MB，含 uuid）
app/src/main/res/drawable-nodpi/bg_sakura_1..5.jpg   5 张随机轮播背景（素材取自 流歌\pic）
app/src/main/res/anim/bg_fade_in.xml / bg_fade_out.xml   背景轮播淡入淡出
THIRD_PARTY_NOTICES.md               Vosk/JNA 等第三方许可
```

状态机：

```
IDLE → ALERT → SPEAKING → LISTEN_DECISION(4s) → LISTEN_REPLY(12s) → LISTEN_CONFIRM(12s) → 发送
         ↓ 取消/重听      ↓ 不回/静音/超时 → 下一条       ↓ 取消/听不清 → 取消，绝不发送
       停止/重读
```

发送安全策略：

- 只有识别结果包含确认词、且不含否定词时才发送
- 第一轮听不清会重问一次，第二轮仍不清楚直接取消
- 收音超时、识别服务报错、TTS 异常都不会触发发送
- 发送失败只做保留/重试/复制，不会把失败文本发到错误的人

## 10. 隐私与安全

- APK 没有申请 `INTERNET` 权限，应用本身不联网、无统计、无广告
- 通知内容只在手机本地处理，不写入日志、不上传
- 离线 Vosk 识别完全在本地运行，音频不离开手机
- 发送失败时，只有你点「复制并打开QQ」才会把回复内容写入剪贴板并打开 QQ
- 如果选择「系统语音识别」，音频由系统识别服务处理，是否上传取决于该系统服务，请自行确认
- TTS 由你选择的系统 TTS 引擎处理；第三方引擎的隐私策略与本应用无关
- 通知使用权可以读取全部应用通知，这是系统机制；代码按包名只处理 `com.tencent.mobileqq` / `com.tencent.qqlite`
- 骑行安全优先：任何需要看屏幕/手动输入的情况，先靠边停车
